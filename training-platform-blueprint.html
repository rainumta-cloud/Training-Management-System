System Blueprint

ระบบจัดการฝึกอบรมออนไลน์ (Training Management System)

แพลตฟอร์มเรียนผ่านวิดีโอสำหรับพนักงาน พร้อม CMS สำหรับแอดมินอัปโหลดคอร์ส บังคับดูจบก่อนสอบ ผ่านเกณฑ์ 70% ถึงจะนับว่า Complete และมีแดชบอร์ดสรุปผลให้ผู้ดูแลติดตามภาพรวม

Self-host video บนเซิร์ฟเวอร์บริษัท Email/Password Login ผู้ใช้ 500–5,000 คน อัปเดต 19 ส.ค. 2569
01

ภาพรวมระบบ

ขอบเขตหลักและกติกาที่ต้องยึดตลอดการออกแบบ

ระบบแบ่งเป็นสองฝั่งที่ทำงานบนโครงสร้างข้อมูลเดียวกัน คือฝั่ง ผู้เรียน (Member) ที่เข้ามาเรียนคอร์สผ่านเบราว์เซอร์ และฝั่ง ผู้ดูแล (Admin/CMS) ที่จัดการเนื้อหา ข้อสอบ และดูภาพรวมผลการเรียน

กติกาหลักที่ล็อกไว้ตั้งแต่ต้น เพื่อให้การออกแบบฐานข้อมูลและ flow สอดคล้องกันทั้งระบบ:

  • ผู้เรียนต้อง ดูวิดีโอจนจบ (ตามเกณฑ์ที่กำหนด) ก่อนปุ่ม "ทำข้อสอบ" จะปลดล็อก
  • ทำข้อสอบได้คะแนน ≥ 70% ถึงจะนับสถานะคอร์สเป็น Complete
  • วิดีโอทั้งหมดจัดเก็บและสตรีมจาก เซิร์ฟเวอร์ของบริษัทเอง ไม่พึ่ง cloud ภายนอก
  • สมัคร/ล็อกอินด้วย อีเมล + รหัสผ่าน แบบง่าย ไม่ผูก SSO ในเฟสแรก
02

บทบาทผู้ใช้และ Flow การทำงาน

เส้นทางของผู้เรียนหนึ่งคอร์ส และงานประจำของแอดมิน

Member Journey — เรียนหนึ่งคอร์สจนจบ

1

สมัครสมาชิก / ล็อกอิน

กรอกอีเมล ตั้งรหัสผ่าน ยืนยันผ่านลิงก์อีเมล (ครั้งเดียว)

2

เลือกคอร์สจากแคตตาล็อก

ดูรายละเอียด บทเรียนย่อย ระยะเวลารวม และสถานะความคืบหน้าเดิม (ถ้าเคยเข้าเรียน)

3

ดูวิดีโอแต่ละบทเรียน

ระบบนับเวลาที่ดูจริงเบื้องหลัง ป้องกันการลากข้ามเพื่อเลี่ยงเนื้อหา

4

ปลดล็อกแบบทดสอบ

เมื่อดูครบทุกบทเรียนถึงเกณฑ์ ปุ่ม "ทำข้อสอบ" จึงจะกดได้

5

ทำข้อสอบและดูผลทันที

สุ่มคำถามจากคลังข้อสอบ ตรวจให้คะแนนอัตโนมัติเมื่อส่งคำตอบ

6

ผ่าน ≥ 70% → Complete

ไม่ผ่าน ให้ทบทวนเนื้อหาแล้วสอบใหม่ได้ตามจำนวนครั้งที่แอดมินกำหนด

Admin Journey — งานจัดการเนื้อหาและติดตามผล

1

สร้างคอร์สและอัปโหลดวิดีโอ

ตั้งชื่อ คำอธิบาย จัดลำดับบทเรียน อัปโหลดไฟล์วิดีโอเข้าระบบ (ประมวลผลเป็น HLS เบื้องหลัง)

2

สร้างคลังข้อสอบ

เพิ่มคำถามแบบเลือกตอบ กำหนดจำนวนข้อ/เกณฑ์ผ่าน/จำนวนครั้งที่สอบซ้ำได้ต่อคอร์ส

3

เผยแพร่คอร์สให้กลุ่มผู้เรียน

เลือกเผยแพร่ทั้งบริษัทหรือเฉพาะแผนก/กลุ่มที่กำหนด

4

ติดตามผลผ่านแดชบอร์ด

ดูอัตราความสำเร็จ คะแนนเฉลี่ย และผู้เรียนที่ยังไม่เริ่ม/ไม่ผ่าน

03

ฟีเจอร์หลักแบ่งตามฝั่งผู้ใช้

ขอบเขตฟีเจอร์ของ MVP สำหรับผู้เรียนและผู้ดูแล

ฝั่งผู้เรียน Member

หน้าเว็บสำหรับพนักงานทั่วไป

  • สมัคร/ล็อกอิน/ลืมรหัสผ่านยืนยันตัวตนผ่านอีเมลบริษัท
  • แคตตาล็อกคอร์สค้นหา จัดหมวดหมู่ ดูสถานะ (ยังไม่เริ่ม/กำลังเรียน/จบแล้ว)
  • วิดีโอเพลเยอร์พร้อม progress barบันทึกจุดที่ดูล่าสุด กลับมาดูต่อได้
  • แบบทดสอบท้ายคอร์สปลดล็อกเมื่อดูวิดีโอครบ แสดงผลคะแนนทันที
  • ประวัติการเรียนของตัวเองคอร์สที่จบแล้ว คะแนนที่ได้ ใบประกาศนียบัตร (ถ้ามี)

ฝั่งผู้ดูแล Admin / CMS

แผงควบคุมสำหรับทีมจัดฝึกอบรม

  • จัดการคอร์สและบทเรียนสร้าง/แก้ไข/เรียงลำดับ/เผยแพร่หรือซ่อนคอร์ส
  • อัปโหลด & จัดการวิดีโอติดตามสถานะแปลงไฟล์ ขนาด ความยาว ที่จัดเก็บ
  • สร้างคลังข้อสอบตั้งเกณฑ์ผ่าน จำนวนข้อสุ่ม จำนวนครั้งที่สอบซ้ำได้
  • จัดการผู้ใช้และสิทธิ์เพิ่ม/ปิดการใช้งานผู้ใช้ กำหนดแอดมินเพิ่ม แบ่งกลุ่ม/แผนก
  • แดชบอร์ดสรุปผลอัตราจบคอร์ส คะแนนเฉลี่ย รายชื่อค้างสอบ ส่งออกรายงาน
04

สถาปัตยกรรมระบบและ Tech Stack ที่แนะนำ

ออกแบบให้ deploy บนเซิร์ฟเวอร์บริษัทได้จริง รองรับผู้ใช้ระดับพันคนและวิดีโอ self-host

ชั้นระบบเทคโนโลยีที่แนะนำเหตุผล
Frontend Next.js + TypeScript SSR หน้าแคตตาล็อกให้โหลดเร็ว ทีมหาคนต่อยอดง่าย ใช้ร่วมกับ UI kit อย่าง shadcn/ui ได้ทันที
Backend API Node.js (NestJS) แยกโมดูล Auth / Course / Quiz / Reporting ชัดเจน เหมาะกับทีมขนาดเล็ก-กลาง ดูแลง่ายกว่าคุมทุกอย่างใน Next.js API routes
ฐานข้อมูล PostgreSQL รองรับ query เชิงสถิติสำหรับแดชบอร์ดได้ดี มี JSONB เก็บโครงสร้างคำถามข้อสอบที่ยืดหยุ่น
วิดีโอ FFmpeg → HLS + Nginx แปลงไฟล์เป็นหลายบิตเรตเพื่อ stream ลื่นตามความเร็วเน็ตผู้ใช้ โดยยังเก็บไฟล์ทั้งหมดบนเซิร์ฟเวอร์บริษัท
คิวงานเบื้องหลัง Redis + BullMQ แปลงไฟล์วิดีโอใช้เวลา ต้องทำแบบ background job ไม่บล็อกหน้าอัปโหลดของแอดมิน
Deploy Docker Compose รวมทุกบริการเป็นชุดเดียว ติดตั้งซ้ำบนเซิร์ฟเวอร์บริษัทได้ง่าย ทีม IT ดูแลต่อไม่ยาก

หมายเหตุ: ถ้าทีม IT บริษัทถนัด .NET/SQL Server และมี Windows Server อยู่แล้ว สามารถสลับเป็น ASP.NET Core + SQL Server + IIS ได้ในแนวคิดสถาปัตยกรรมเดียวกัน — ส่วนที่ต้องคงไว้คือ FFmpeg สำหรับแปลงวิดีโอและคิวงานเบื้องหลัง

05

กลไกจับเวลา & บังคับดูจบก่อนสอบ

ป้องกันการลากวิดีโอข้ามเพื่อเลี่ยงเนื้อหา โดยไม่ทำให้ผู้เรียนดูต่อจากจุดเดิมไม่ได้

01 · client

เพลเยอร์ส่ง heartbeat ทุก 5–10 วินาที บอกตำแหน่งเวลาปัจจุบันที่กำลังเล่น

→
02 · server

สะสม "ช่วงเวลาที่ดูจริง" ต่อผู้ใช้ต่อวิดีโอ ไม่นับจุดที่ถูกลากข้ามแบบไม่ผ่านสายตา

→
03 · rule

ล็อกไม่ให้ลากไปเกินจุดไกลสุดที่เคยดูถึง (บวก buffer สั้นๆ) แต่ดูซ้ำจุดเดิมได้ตามปกติ

→
04 · unlock

เมื่อสัดส่วนที่ดูจริง ≥ 95% ของความยาววิดีโอ ระบบปลดล็อกปุ่มทำข้อสอบของบทเรียนนั้น

ทางเลือกออกแบบ: เกณฑ์ 95% และการล็อกการลากข้ามควรเป็นค่าที่ปรับได้ต่อคอร์ส (โหมดเข้มงวด vs โหมดปล่อยอิสระ) เพราะบางคอร์สอาจต้องการความยืดหยุ่นให้พนักงานอาวุโสข้ามเนื้อหาที่รู้แล้วได้

09

ข้อกำหนดที่ไม่ใช่ฟังก์ชัน

Scale ที่ต้องรองรับ พื้นที่จัดเก็บโดยประมาณ และความปลอดภัยของเนื้อหา

ปริมาณผู้ใช้

ออกแบบรองรับ 500–5,000 คน และคอร์สหลักสิบถึง ~100 คอร์ส — เพียงพอด้วยเซิร์ฟเวอร์แอปเดียวและ DB แยกอินสแตนซ์ ไม่จำเป็นต้อง scale แนวนอนตั้งแต่วันแรก

พื้นที่จัดเก็บวิดีโอ (ตัวอย่างประมาณการ)

วิดีโอ 1080p HLS ≈ 0.6–1 GB/ชม. หากมี 100 คอร์ส เฉลี่ยคอร์สละ 2 ชม. ≈ 120–200 GB รวมทุกบิตเรต ควรเผื่อพื้นที่ 2–3 เท่าและวางแผน backup แยกดิสก์

ป้องกันการดาวน์โหลด/แชร์ลิงก์

ใช้ signed URL ที่หมดอายุไม่กี่นาทีต่อ segment วิดีโอ ผูกกับ session ผู้ใช้ ป้องกันการก็อปลิงก์ไปเปิดนอกระบบ

ความปลอดภัยบัญชีผู้ใช้

รหัสผ่าน hash ด้วย bcrypt/argon2, บังคับ HTTPS, จำกัดจำนวนครั้ง login ผิดพลาด (rate limit) ป้องกัน brute force

ความพร้อมใช้งาน

สำรองข้อมูล DB รายวัน และแยก process แปลงวิดีโอออกจาก API server เพื่อไม่ให้การอัปโหลดกระทบผู้เรียนที่กำลังใช้งาน

Audit trail

บันทึก log การแก้ไขคอร์ส/ข้อสอบ และการเปลี่ยนสถานะคะแนนของแอดมิน เผื่อกรณีต้องตรวจสอบย้อนหลัง

10

แผนดำเนินงาน

ลำดับการสร้างจริง ตั้งแต่โครงพื้นฐานจนถึงฟีเจอร์เสริม

0

เตรียมโครงสร้าง 1–2 สัปดาห์

  • เตรียมเซิร์ฟเวอร์/Docker environment ที่บริษัท ออกแบบ schema ฐานข้อมูลฉบับสมบูรณ์
  • ตกลง design system หน้าตาเว็บ และ endpoint หลักของ API
1

MVP 4–6 สัปดาห์

  • สมัคร/ล็อกอิน, แคตตาล็อกคอร์ส, อัปโหลด+เล่นวิดีโอพร้อมนับเวลาดูพื้นฐาน
  • ระบบข้อสอบและคำนวณผ่าน/ไม่ผ่าน, CMS จัดการคอร์ส/คำถามเบื้องต้น
2

รายงานและความสมบูรณ์ 3–4 สัปดาห์

  • แดชบอร์ดพร้อมกราฟ, ส่งออกรายงาน Excel, ใบประกาศนียบัตร PDF
  • ปรับ pipeline แปลงวิดีโอเป็นหลายบิตเรตอัตโนมัติ, ระบบแจ้งเตือนอีเมล (คอร์สใหม่/ใกล้ครบกำหนด)
3

ต่อยอด ตามรอบใช้งานจริง
